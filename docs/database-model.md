# ข้อมูลการจองและประวัติ

- `customers` เป็นข้อมูลผู้เข้าพัก; `accounts.customer_id` เป็นบัญชีออนไลน์ที่เชื่อมกับลูกค้าได้ แต่ walk-in ไม่จำเป็นต้องมีบัญชี พนักงานค้นหาและเลือกประวัติเดิมด้วยตนเอง ไม่รวมลูกค้าอัตโนมัติ
- `bookings.customer_id` ระบุลูกค้าของการเข้าพัก ส่วน `bookings.account_id` ระบุบัญชีที่สร้างรายการออนไลน์และใช้กำหนดสิทธิ์; walk-in เก็บค่าว่าง การเชื่อมบัญชีในภายหลังจึงไม่ทำให้สิทธิ์ของรายการเดิมเปลี่ยนโดยอัตโนมัติ ต้องกำหนดนโยบายและตรวจข้อมูลก่อนเปลี่ยนความหมายนี้
- `reviews` อ้างถึงการจอง และตรวจสิทธิ์ผู้เขียนจากบัญชีผู้จอง ไม่เก็บบัญชีผู้เขียนซ้ำ `review_author_legacy` เก็บค่าเดิมเฉพาะข้อมูลก่อน migration เพื่อรองรับการตรวจสอบและย้อนกลับ
- `booking_service_rooms` เชื่อมบริการรายห้องกับ `booking_rooms` ส่วน `booking_services` เก็บ `booking_id` เพียงแห่งเดียว Trigger ตรวจว่าบริการและห้องอยู่ในการจองเดียวกัน และป้องกันย้าย booking ของรายการที่เชื่อมแล้ว บริการระดับการจองและรายการเก่าที่ระบุห้องไม่ได้ไม่มีแถวในตารางเชื่อม Migration 005 จับคู่รายการอาหารเช้าเก่าเฉพาะเมื่อ snapshot ระบุห้องได้แน่นอน
- ราคาต่อคืนที่จอง ยอดรวม ยอดมัดจำ และ `price_snapshot` เป็นข้อมูลราคา ณ เวลาทำสัญญาและยอดสรุปเพื่อการทำงาน ไม่คำนวณย้อนหลังจากราคาปัจจุบันโดยอัตโนมัติ ข้อมูลสรุปและ snapshot จึงเป็นการทำซ้ำอย่างมีจุดประสงค์ ไม่ใช่ข้ออ้างว่าทุกตารางเป็น 3NF แบบเคร่งครัด
- การชำระในโปรเจกต์ยังเป็น workflow จำลองและรอฝ่ายบัญชี ไม่ได้เชื่อมเครือข่ายบัตร ธนาคาร หรือ PayPal ไม่มีการรับข้อมูลบัตร และไม่มีการโอนเงินจริง

Migration 002–006 ตรวจสอบก่อนทำ DDL หลักซ้ำและใช้ advisory lock กันการรัน migration พร้อมกัน Migration 006 ต้องมีสิทธิ์สร้าง trigger โดย Docker Compose สำหรับโครงงานกำหนด `log-bin-trust-function-creators=1` ไว้แล้ว สำหรับ MySQL นอก Compose ผู้ดูแลระบบต้องตั้งค่านี้หรือให้สิทธิ์ที่เหมาะสมก่อนรัน หยุดแอปขณะ migrate หรือ rollback เพราะ MySQL DDL ไม่ได้ย้อนกลับทั้ง migration โดยอัตโนมัติ สำรองฐานข้อมูลก่อนเสมอ และตรวจจำนวนบริการที่ไม่เชื่อมห้องหลังย้าย

Rollback 006 ใช้ `db/rollbacks/006_service_room_normalization.sql` เมื่อแอปหยุดแล้ว จากนั้นใช้โค้ดเวอร์ชันก่อน 006 และตรวจผลก่อนเปิดบริการอีกครั้ง สคริปต์คืน `booking_room_id` พร้อม foreign key เดิมก่อนลบตารางเชื่อม ข้อมูล `review_author_legacy` เป็นเอกสารสำหรับการย้ายข้อมูล ไม่ใช่ตารางที่ใช้แสดงรีวิวปัจจุบัน
